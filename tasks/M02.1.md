# M02.1 — Reparar bootstrap de aislamiento del ejecutor

## Decisión aprobada

Joaquín + ChatGPT, 2026-10-01: corregir el fallo de infraestructura encontrado por la primera
ejecución real de M03. Mantener el aislamiento de subprocessos de Claude; no resolver el problema
desactivando `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`.

Esta es una reparación mínima del ejecutor M02. No cambia producto ni amplía la autonomía.

## Problema

El run real de GitHub Actions `36864248192` disparado por el issue #2 pasó el `gate`, encontró
`CLAUDE_CODE_OAUTH_TOKEN` presente y llegó al step `Claude ejecuta la TASK`, pero Claude Code no
alcanzó a ejecutar M03. La instalación abortó tres veces con:

```text
error: bubblewrap is required for subprocess env scrubbing and isolation.
Install with: sudo apt-get install -y bubblewrap, set sandbox.bwrapPath in managed settings,
or set CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=0 to disable (loses subprocess isolation).
```

Resultado observado del run:
- `gate`: success
- `claude`: failure
- `publish`: success con verificación `NOTHING`; no publicó rama
- `notify`: success
- no existe `auto/m03-issue-2`
- el comentario automático del issue #2 registró Claude `failure`, verificación `NOTHING`
- no hubo merge ni deploy.

La causa de integración es que nuestro workflow fuerza
`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, mientras la versión fijada del action sólo ejecuta su step
interno de instalación de dependencias de aislamiento bajo otra condición. No debemos depender de
esa condición implícita.

## Resultado esperado

El job `claude` prepara explícitamente las dependencias necesarias para ejecutar Claude Code con
`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` en el runner Linux, antes de invocar
`anthropics/claude-code-action`.

La solución debe ser mínima, fail-closed y verificable. Si la dependencia de aislamiento no puede
instalarse o verificarse, el job debe fallar antes de entregar el OAuth token al action.

Además, actualizar tests/documentación del ejecutor para que este requisito quede cubierto y no
regrese silenciosamente.

## Acceptance criteria

1. El workflow mantiene `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`.
2. Antes de `anthropics/claude-code-action`, el job `claude` instala/prepara explícitamente las
   dependencias Linux necesarias para el aislamiento, incluyendo `bubblewrap`.
3. El workflow verifica que `bwrap` existe antes de entregar la credencial de Claude al action;
   si no existe, falla cerrado.
4. En runners donde corresponda, se contempla la restricción de user namespaces/AppArmor necesaria
   para que bubblewrap funcione; no basta comprobar sólo que el binario existe si el sandbox no
   puede operar.
5. La instalación usa privilegios sólo para preparar el runner; Claude sigue ejecutándose sin
   permisos de push y con los límites M02 existentes.
6. No se amplían permisos GitHub ni superficie de escritura.
7. Tests estáticos del ejecutor prueban que scrub sigue activo, que la preparación/verificación de
   aislamiento ocurre antes del action y que no existe una salida `SCRUB=0`.
8. Los tests M02/handoff relevantes pasan; los fallos históricos no se presentan como regresiones
   de M02.1.
9. `git diff 6324b1f HEAD -- src/` permanece vacío.
10. Se crea `reports/M02.1_REPORT.md` y se actualiza `CURRENT_STATE.md` en el mismo commit.
11. El REPORT registra que M03 original sigue siendo FAIL/BLOCKED como prueba E2E; M02.1 no puede
    declarar `E2E_REAL_PROVEN` hasta un nuevo run automático exitoso.
12. No hay merge, deploy ni ejecución automática nueva iniciada por Claude.
