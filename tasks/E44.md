# E44 — Benchmark online: 20 MEJORAR + 20 CREAR

## Decisión aprobada

Joaquín aprobó el 2026-10-02 dejar de ampliar features y someter los dos motores core de ESCALÍMETRO a una campaña real y repetible con propiedades encontradas online.

Dos pistas separadas:

1. **MEJORAR PLANO — 20 propiedades reales**
   - existe un plano publicado;
   - input = ese plano tal como lo publica el corredor;
   - output = Plano Corporativo;
   - evaluar ANTES / DESPUÉS, fidelidad geométrica, legibilidad, publicabilidad y trabajo humano.

2. **CREAR PLANO — 20 propiedades reales**
   - la publicación debe tener fotos/datos suficientes Y un plano real disponible;
   - el plano real se captura como **GROUND TRUTH HIDDEN FROM ENGINE**;
   - el motor sólo recibe fotos + datos declarados/evidencia pública permitida;
   - se reconstruye primero, se permiten correcciones humanas estructuradas, y **sólo al final** se revela/compara el plano real;
   - reutilizar E37 Reconstruction Lab. Nunca filtrar el ground truth al motor.

Objetivo de muestra: **40 propiedades reales calificadas = 20 + 20**. No sustituir casos faltantes con fixtures, sintéticos o duplicados.

La hipótesis “90% IA / 10% humano” se **mide**; no se asume ni se fuerza.

Esta TASK es un experimento de producto/calidad, no una excusa para construir otra suite.

## Problema

Ya existe el circuito técnico de Plano Corporativo hasta entrega (E41–E43) y el Reconstruction Lab ciego (E37), pero todavía no sabemos si los resultados son suficientemente buenos sobre una muestra real.

Una demo o un test unitario no responde:
- ¿MEJORAR conserva fielmente la planta y realmente la hace más publicable?
- ¿CREAR reconstruye una planta útil sin mirar el plano real?
- ¿qué tipos de propiedad/evidencia funcionan o fallan?
- ¿cuántos prompts/minutos humanos requiere cada caso?
- ¿dónde falla sistemáticamente la geometría?
- ¿qué debe programarse después, basado en evidencia y no intuición?

## Resultado esperado

### A. Protocolo común de corpus

1. Crear una estructura de campaña E44 persistente y mínima, reutilizando las piezas existentes en vez de una app paralela.
2. Cada caso real tiene un ID opaco/interno, pista `IMPROVE` o `CREATE`, source URL(s), fecha de captura, fuente, tipo de propiedad, m² publicados si existen, lista de assets/evidencia y estado.
3. Evitar duplicados: misma propiedad/unidad no cuenta dos veces dentro de una pista. Si una misma propiedad se usa excepcionalmente en ambas pistas, declararlo; el objetivo preferido son 40 propiedades distintas.
4. Sólo cuentan casos de oficinas/comercialización inmobiliaria compatibles con el North Star actual.
5. No guardar PII innecesaria de corredores/contactos. El benchmark estudia propiedades y material comercial, no personas.

### B. Pista MEJORAR — 20 casos

Para cada caso:
1. conservar el plano original capturado como evidencia inmutable;
2. procesarlo por el camino real de MEJORAR / Plano Corporativo existente;
3. no corregir geometría silenciosamente sólo para mejorar la nota;
4. guardar output final y comparación visual ANTES / DESPUÉS;
5. registrar:
   - si el pipeline llegó a output;
   - errores/ambigüedades de escala, perímetro, núcleo, acceso, pilares, fachada/luz;
   - fidelidad geométrica observada;
   - legibilidad;
   - publicabilidad comercial;
   - número de intervenciones/prompts/correcciones humanas;
   - minutos humanos, si se registran;
   - rating Joaquín `EXCELENTE / BUENO / MALO / PESIMO` cuando exista;
   - si requirió edición técnica/CAD manual.
6. No inventar score compuesto. Mostrar dimensiones por separado.
7. El output “bonito” con geometría incorrecta es fallo, no éxito.

### C. Pista CREAR — 20 casos blind

Criterio de inclusión:
- fotos/evidencia visual suficientes para intentar reconstrucción;
- m²/datos declarados cuando existan;
- plano real disponible para ground truth;
- el GT debe poder aislarse antes de ejecutar.

Para cada caso:
1. capturar primero todos los assets y provenance;
2. cargar el plano real mediante la separación `GROUND TRUTH HIDDEN FROM ENGINE` de E37;
3. probar adversarialmente que el adapter no recibe GT/path/hash/metadata derivable antes del reveal;
4. input permitido = fotos + datos declarados/evidencia pública explícitamente registrada; **no plano real**;
5. ejecutar un motor real registrado. Fixtures no cuentan para N=20;
6. si falta credencial/proveedor, marcar `BLOCKED_MISSING_CREDENTIAL`; no simular;
7. permitir correcciones humanas sólo mediante el flujo estructurado de E37 (child run / lenguaje natural), sin editar el plano a mano;
8. fijar un punto de cierre de la reconstrucción antes de reveal;
9. revelar GT explícitamente y comparar;
10. registrar por separado:
   - inventario de recintos;
   - conexiones/adyacencias;
   - posiciones relativas;
   - forma global;
   - proporciones/áreas cuando sean comparables;
   - puertas/conexiones relevantes cuando haya evidencia;
   - incertidumbres declaradas;
   - prompts humanos;
   - minutos humanos;
   - rating final;
   - necesidad de CAD/manual técnico;
   - errores dominantes.
11. No inventar una precisión automática donde no exista una métrica fiable; permitir juicio humano estructurado.
12. Las runs blind quedan inmutables después de reveal.

### D. Evidencia visual y revisión Joaquín

Para cada caso completado:
- fuente;
- input permitido;
- output;
- para MEJORAR: antes/después;
- para CREAR: reconstrucción antes del reveal + GT después del reveal;
- datos/medidas;
- intervención humana;
- fallo principal;
- espacio para rating/comentario Joaquín.

Crear un índice simple de campaña que permita a Joaquín revisar casos uno por uno sin navegar tablas técnicas.

### E. Resumen de campaña

El resumen final debe mostrar, **sin inventar ni esconder faltantes**:
- N capturado / N ejecutado / N completado por pista;
- distribución de ratings;
- tasa de pipeline success;
- intervenciones/prompts humanos;
- tiempo humano cuando exista;
- frecuencia de tipos de error;
- qué evidencia parece necesaria para CREAR;
- ejemplos representativos buenos y malos;
- casos excluidos y motivo;
- resultados faltantes por credencial/red/material;
- ninguna conclusión causal/comercial que la muestra no soporte.

No declarar “vendible”, “90/10 logrado” ni “motor validado” sólo por promedio. Joaquín decide la calidad mirando la evidencia.

## Acceptance criteria

### Instrumento/campaña
1. Existe un manifiesto/corpus E44 reproducible con provenance y estados.
2. Distingue inequívocamente `IMPROVE` y `CREATE`.
3. Detecta/evita duplicados básicos.
4. Los casos no ejecutados no inflan N.
5. Hay índice de revisión humana con outputs/evidencia por caso.
6. Los resultados se pueden regenerar/auditar sin depender de memoria del operador.

### MEJORAR
7. Meta = 20 casos reales únicos.
8. Cada caso completado conserva plano original + Plano Corporativo + before/after + métricas separadas.
9. El flujo usa el camino real de Plano Corporativo, no un renderer de prueba.
10. Se registran errores geométricos y trabajo humano.
11. Si no se alcanzan 20 por falta de corpus/material, status no puede ser PASS completo.

### CREAR
12. Meta = 20 casos reales blind.
13. Cada caso tiene GT real disponible pero oculto durante reconstrucción.
14. Test/guard adversarial confirma ceguera de GT.
15. Fixtures/fakes no cuentan.
16. Cada caso ejecutado usa un motor real registrado y registra model/version/prompt/costo/latencia cuando estén disponibles.
17. Correcciones crean child runs; no sobrescriben.
18. Reveal ocurre sólo después del cierre blind.
19. Comparación post-reveal conserva run original.
20. Si falta `OPENAI_API_KEY` u otra credencial requerida, el resultado es explícitamente BLOCKED/PARTIAL; nunca fake success.
21. Si no se alcanzan 20 por falta de corpus/material/credencial, status no puede ser PASS completo.

### Seguridad/regresión
22. Ninguna PII innecesaria aparece en outputs públicos/evidencia.
23. No se abre Internet al executor.
24. `git diff 6324b1f HEAD -- src/` vacío salvo DECISION_REQUIRED previo; el objetivo de E44 es medir, no cambiar el motor.
25. E43 sigue verde.
26. Tests nuevos cubren manifest/provenance, conteo honesto, duplicados, blindness, reveal e inmutabilidad de resultados.
27. `reports/E44_REPORT.md` + `CURRENT_STATE.md`.
28. Al menos un commit real posterior a la TASK.
29. Sin merge/deploy/main.

### Verdad del experimento
30. **PASS de E44 requiere 20 MEJORAR + 20 CREAR realmente completados.**
31. Si la infraestructura queda lista pero los casos reales no pueden ejecutarse en este entorno, usar **PARTIAL** y listar exactamente qué falta y cómo correr la campaña sin debilitar seguridad.
32. Nunca convertir “40 URLs encontradas” en “40 casos probados”.
