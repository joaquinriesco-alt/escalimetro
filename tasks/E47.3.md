# E47.3 — Cerrar H03: claim atómico antes de gasto

## Decisión aprobada
Descomposición mecánica de E47 ya aprobada por Joaquín. E47.2 cerró H01 y esta continuación implementa únicamente E46-H03. No hay nueva decisión de producto.

## Problema
E46 demostró que dos requests prácticamente simultáneos a PROCESAR pueden atravesar el chequeo previo y crear dos runs, con potencial doble llamada pagada. CORREGIR usa una estructura equivalente. Esto es un BLOCKER pre-piloto.

## Contexto canónico
Base exacta: auto/e47_2-issue-21. Evidencia primaria: reports/E46_REPORT.md, hallazgo H03; tests/test_e46_adv_resilience.py. Mantener H01 cerrado. No tocar H10 ni HIGH pendientes. Mantener campaña 20+20, DEMO fuera del N, GT ciego, cero llamadas pagadas en tests. No deploy/merge/main. No .github ni src.

## Resultado esperado
Implementar un claim atómico/idempotente antes de cualquier acción que pueda crear un run o invocar un proveedor en:
- PROCESAR CREAR
- PROCESAR MEJORAR cuando corresponda al mismo patrón
- CORREGIR CREAR

Dos requests concurrentes para la misma acción deben producir exactamente un claim efectivo, un run y como máximo una invocación al adaptador simulado. El segundo request debe terminar de forma segura e idempotente, sin 500, sin run duplicado y sin gasto adicional. Preferir un mecanismo simple y durable compatible con el almacenamiento actual (archivo exclusivo, singleton atómico o equivalente) y que sobreviva al doble request sin introducir un servicio externo.

IMPORTANTE: implementar el cambio mínimo, correr primero las reproducciones H03/F4/F7 y un test equivalente para CORREGIR, y COMMITTEAR inmediatamente cuando pasen. Después, si queda tiempo, correr regresión focal. No investigar otros hallazgos.

## Acceptance criteria
1. Reproducción H03 con barrera/concurrencia forzada queda cerrada.
2. Dos PROCESAR CREAR simultáneos producen un solo run y una sola llamada simulada.
3. Dos CORREGIR simultáneos producen un solo child run y una sola llamada simulada.
4. El segundo request concurrente responde sin 500 y no altera el resultado del primero.
5. Si MEJORAR comparte el defecto demostrado en H03/F7, queda protegido por el mismo principio con un solo efecto.
6. El claim se registra antes de cualquier llamada potencialmente pagada.
7. Repetir una acción ya completada sigue siendo seguro/idempotente según contrato existente.
8. H01 y su suite de ceguera siguen verdes.
9. Suites E44/E45/E45.2 y tests E46 relevantes de resilience pasan.
