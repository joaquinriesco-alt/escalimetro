# E41 — Pedido público mínimo de Plano Corporativo

## Decisión aprobada

Implementar el paso 2 del plan E39: convertir el CTA público de E40 en un pedido real y mínimo de **Plano Corporativo**.

El formulario debe respetar la dirección aprobada de ESCALÍMETRO: **PLANOS QUE AYUDAN A VENDER**, con fricción mínima. Para este producto de entrada el cliente ya tiene un plano.

Input público obligatorio, y nada más:
- **email**;
- **plano existente** en PDF, JPG o PNG.

No pedir teléfono, nombre, empresa, dirección, fotos, programa arquitectónico, número de personas, estilo ni precio. Si después hace falta más información, se pide después; no debe bloquear la captura inicial.

Esta TASK implementa **recepción y persistencia honesta del pedido**, no la producción automática del plano ni su entrega.

## Problema

E40 dejó `/planos/` público y el CTA **SUBIR PROPIEDAD**, pero `/planos/solicitar` sólo dice «Solicitud próximamente». Hoy un corredor interesado no puede dejar su plano ni un medio de contacto.

Necesitamos cerrar el primer tramo comercial real:

**landing → subir plano → dejar email → pedido recibido**

sin convertir esta TASK en checkout, CRM, motor automático ni suite de marketing.

## Resultado esperado

1. `/planos/solicitar` deja de ser placeholder y muestra un formulario público extremadamente simple.
2. Campos obligatorios visibles: **email** + **archivo del plano**.
3. Acepta PDF/JPG/JPEG/PNG usando límites y sanitización coherentes con el proyecto.
4. Un POST válido:
   - valida los dos inputs;
   - guarda el archivo bajo `ESCALIMETRO_DATA_DIR` o la abstracción de storage existente;
   - persiste un registro mínimo del pedido con ID opaco, email, referencia segura al archivo, timestamp y estado inicial `RECEIVED` (o equivalente ya existente);
   - no ejecuta motor, layout, staging ni proveedor externo;
   - devuelve una confirmación clara: el pedido fue recibido.
5. Un POST inválido explica el error sin crear pedido parcial.
6. Refresh/reintento no debe fingir múltiples pedidos silenciosamente si el framework ya ofrece una solución simple; preferir POST/Redirect/GET.
7. La landing conserva su CTA y éste sigue apuntando a `/planos/solicitar`.
8. El pedido queda disponible para que una TASK posterior implemente procesamiento/entrega; no construir esa fase ahora.
9. Mantener la superficie pública aislada de navegación y herramientas internas.
10. Mantener HTTP Basic en todas las rutas internas existentes.

La implementación puede elegir el detalle técnico mínimo dentro de `webapp/` (tabla pequeña propia o abstracción existente) siempre que no cree infraestructura externa ni acople el formulario al motor.

## Acceptance criteria

1. `GET /planos/solicitar` responde 200 sin Authorization.
2. La página muestra exactamente los dos inputs obligatorios de negocio: email + plano.
3. El formulario no contiene los campos prohibidos de esta TASK.
4. `POST /planos/solicitar` con email válido + PDF/JPG/JPEG/PNG válido crea exactamente un pedido persistido y conserva el archivo de forma segura.
5. El pedido tiene identificador no secuencial/opaque hacia el usuario, timestamp y estado inicial.
6. Después del POST válido existe confirmación inequívoca y un refresh no repite el POST.
7. Email ausente/inválido o archivo ausente/no permitido produce error visible y **cero pedidos parciales**.
8. El nombre original del archivo no permite path traversal; usar sanitización/renombrado seguro.
9. No hay llamadas externas ni ejecución del motor en el POST.
10. El CTA de `/planos/` sigue llevando al formulario.
11. Rutas internas representativas continúan exigiendo HTTP Basic.
12. Tests nuevos cubren happy path, validaciones, persistencia, archivo, PRG/no duplicación y protección interna.
13. Tests relevantes preexistentes de E40 y webapp siguen verdes.
14. `git diff 6324b1f HEAD -- src/` es vacío.
15. `reports/E41_REPORT.md` y `docs/ai-development/CURRENT_STATE.md` quedan actualizados en el mismo commit final.
16. Existe al menos un commit real de implementación después del commit de la TASK.
17. Sin merge, deploy ni movimiento de `main`.
