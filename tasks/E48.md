# E48 — Auditoría final de readiness pre-piloto

## Decisión aprobada

Joaquín aprobó ejecutar E48 después de cerrar y auditar los hallazgos prioritarios de E46.

Esta TASK es exclusivamente de auditoría final. No implementa fixes de producto.

Objetivo: intentar romper la rama acumulada actual y emitir un veredicto binario y defendible para el piloto real de 20 MEJORAR + 20 CREAR:

- `READY`: el código está suficientemente seguro y estable para pasar al paso operativo de deploy/configuración y luego ejecutar UN caso real de smoke antes de comenzar la muestra.
- `NOT_READY`: existe al menos un defecto reproducible que puede invalidar la muestra, perder/mezclar evidencia, filtrar el ground truth, provocar costo duplicado/involuntario, bloquear el flujo normal sin recuperación razonable, derribar el panel/casos, o hacer inviable el uso real del piloto.

`READY` NO significa “ya desplegado” ni “motor real validado”. Esta TASK no despliega ni configura credenciales. Si el código queda READY, el siguiente paso será deploy controlado + configuración del proveedor + un único caso real de smoke.

- H03 — doble disparo/doble costo.
- H05 — retry CREAR tras fallo técnico.
- H10 — same-origin global.
- H16 — costo de clasificación de fotos.
- H20 — exclusión que no liberaba duplicados.
- H21 — error técnico del proveedor rompía settle/panel.

Durante la propia auditoría de E47.8 se encontró además la ventana DONE no asentado → segunda corrida; E47.9 la cerró.

Falta una auditoría integrada sobre la rama acumulada. No basta con que cada fix haya pasado su suite focal: hay que probar sus interacciones y revisar si alguno de los MEDIUM/LOW de E46, o un hallazgo nuevo, bloquea realmente el piloto de 40 casos.

La auditoría debe cubrir al menos estas capas:

### A. Regresión de los fixes prioritarios

Reprobar explícitamente H01/H02/H03/H05/H10/H16/H20/H21 y E47.9.

No limitarse a ejecutar tests existentes: intentar variantes razonables alrededor de cada frontera.

### B. Ceguera / contaminación de CREAR

Intentar que el ground truth llegue al motor por variaciones realistas:
- mismo archivo;
- re-encode JPEG;
- resize;
- cambios de calidad;
- rotación 90/180;
- crop leve;
- padding/borde;
- screenshot o transformación simple que siga pareciendo plano.

Distinguir:
- bypass perceptual;
- bloqueo por clasificador de plano;
- falsos positivos sobre fotos normales.

Un bypass que permita que un plano real razonablemente transformado llegue al motor es `NOT_READY`.

Verificar también que:
- ningún GET previo al reveal sirve GT;
- ninguna metadata/evento/request al motor contiene GT, nombre, sha o ruta;
- una corrección no puede ejecutarse después de reveal fuera de banda sin que la campaña lo detecte.

Revisar específicamente E46-H04 y decidir si su reproducción actual bloquea o no el piloto. Si permite que el operador invalide silenciosamente la ceguera dentro de un flujo razonable del piloto, es `NOT_READY`.

### C. Concurrencia / idempotencia / costo

Forzar:
- doble upload idéntico;
- uploads distintos simultáneos;
- doble PROCESAR;
- retry concurrente tras FAILED;
- DONE no asentado + segundo POST;
- FAILED no asentado + segundo POST;
- settle simultáneo/repetido;
- corrección concurrente.

Invariantes:
- máximo una llamada/corrida pagable por intención;
- ninguna pérdida de caso aceptado;
- ningún borrado de evidencia ajena;
- conteos estables;
- historial inmutable.

Cualquier doble llamada pagable o pérdida silenciosa de evidencia/caso es `NOT_READY`.

### D. Fallos / reinicios / corrupción

Revisar los MEDIUM de persistencia E46, especialmente H06/H08 y relacionados.

Simular cuando sea razonable:
- archivo de evento truncado;
- fallo de escritura del manifiesto;
- caída entre create_started y settle;
- corrida huérfana;
- provider timeout/error hostil;
- fallo durante import/create;
- disco/write exception simulada.

Clasificar cada defecto restante:
- `BLOCKS_PILOT`
- `KNOWN_RISK_ACCEPTABLE`
- `NOT_REPRODUCED`

Un único archivo/evento corrupto que razonablemente pueda derribar todo el panel sin recuperación desde la UI debe evaluarse con severidad alta; justificar explícitamente si se acepta o bloquea.
