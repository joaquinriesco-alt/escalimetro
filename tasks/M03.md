# M03 — Prueba real del ejecutor automático

## Decisión aprobada

Joaquín + ChatGPT, 2026-10-01: ejecutar la primera prueba real end-to-end del ejecutor GitHub-native
construido en M02. Joaquín ya autorizó avanzar `main` hasta M02 y autorizó esta prueba al responder
«dale» después de que ChatGPT propusiera M03. El objetivo es comprobar que una TASK aprobada puede
viajar ChatGPT → GitHub Actions → Claude → GitHub → ChatGPT sin que Joaquín abra Claude ni copie
prompts o reportes.

Esta TASK autoriza una ejecución real de Claude Code Action usando el
`CLAUDE_CODE_OAUTH_TOKEN` configurado por Joaquín en GitHub Actions. No autoriza API billing,
merge, deploy ni trabajo de producto.

## Problema

M02 está construido y su workflow ya llegó a la rama default, pero todavía no existe evidencia de
una ejecución real. Necesitamos demostrar el ciclo completo con una tarea deliberadamente inocua,
sin tocar código de producto.

## Resultado esperado

Una ejecución automática real crea la rama `auto/m03-issue-<n>` desde esta TASK y deja evidencia
suficiente para que ChatGPT audite el ciclo sin conversación con Claude.

Claude debe:

1. crear `experiments/M03/executor_smoke.md` con el TASK ID, número de issue, run ID de GitHub
   Actions si está disponible en el entorno, rama de TASK y rama automática;
2. crear `reports/M03_REPORT.md` con el formato del protocolo;
3. actualizar `docs/ai-development/CURRENT_STATE.md` reemplazando el estado obsoleto de M02:
   registrar el `main` remoto actual, el resultado real de M03 y declarar la rama automática de
   M03 como base para la próxima TASK si M03 pasa;
4. actualizar `docs/ai-development/DECISIONS.md` sólo para persistir hechos ya decididos por
   Joaquín: DR-1/DR-9 quedan resueltas por la autorización explícita de avanzar `main` a M02 y
   activar el ejecutor. DR-8 (proteger `main`) sigue pendiente;
5. no declarar `E2E_REAL_PROVEN` salvo que la ejecución real llegue hasta publicación de la rama
   automática y la evidencia sea coherente.

## No hacer

- No tocar `src/`, `webapp/`, `.github/`, `scripts/`, `tasks/`, `.claude/` ni
  `.mcp.json`.
- No cambiar producto, CREAR PLANO, MEJORAR PLANO ni E37.
- No correr Ricardo Lyon ni llamar OpenAI.
- No crear ni modificar secretos.
- No imprimir credenciales.
- No mergear a `main`, no desplegar y no cambiar la rama default.
- No proteger `main` ni cambiar settings administrativos: DR-8 sigue separado.
- No crear M04 ni ninguna TASK posterior.
- No instalar infraestructura ni dependencias nuevas.
- No convertir esta prueba en una refactorización de M02.

## Acceptance criteria

1. La rama de TASK parte exactamente de `m02_github_executor @ edd50e05720cde078cb1f1887f403daaa5d102c8` y el commit inicial agrega sólo `tasks/M03.md`.
2. La ejecución ocurre mediante el workflow de M02, sin invocación manual de Claude por Joaquín.
3. Existe una rama `auto/m03-issue-<n>` descendiente del commit exacto de esta TASK.
4. `experiments/M03/executor_smoke.md` registra TASK ID, issue, run ID si está disponible, task branch y auto branch.
5. Existe `reports/M03_REPORT.md` y permite auditar la prueba sin leer una conversación de Claude.
6. `CURRENT_STATE.md` refleja la verdad remota posterior a M03 y, si PASS, declara la rama automática como base de la próxima TASK.
7. DR-1 y DR-9 sólo se marcan resueltas porque Joaquín ya autorizó y ChatGPT ya ejecutó el fast-forward; DR-8 permanece pendiente.
8. Ningún commit de la implementación toca rutas prohibidas por el verificador de M02.
9. `git diff 6324b1f HEAD -- src/` sigue vacío.
10. No hay merge, deploy, cambio de default branch ni nueva TASK.
11. El REPORT distingue claramente entre workflow disparado, Claude ejecutado, rama publicada y auditoría posterior de ChatGPT; no infiere etapas que no pueda verificar.
12. Si cualquier compuerta o autenticación falla, el resultado es FAIL/PARTIAL/BLOCKED con evidencia; no se simula éxito.

## Evidencia requerida

- Número del issue de transporte y GitHub Actions run ID si el entorno lo expone.
- Commit exacto de la TASK y commit final producido por Claude.
- Nombre de la rama automática.
- Diff de archivos de la rama automática contra el commit de TASK.
- `git diff 6324b1f HEAD -- src/`.
- Tests relevantes del handoff/protocolo que puedan correrse sin convertir el smoke test en trabajo de producto.
- Estado remoto de `main`, task branch y auto branch al cerrar.
- Confirmación explícita de cero merge y cero deploy ejecutados por M03.
- Ningún valor de secreto en evidencia, logs o REPORT.

## Decision gates

Detenerse y reportar si la prueba exige cambiar el workflow, permisos, autenticación, settings de
GitHub, branch protection, producto o doctrina. M03 no arregla el ejecutor durante la misma prueba:
si el mecanismo falla, registra el fallo para que Joaquín + ChatGPT decidan una TASK posterior.

Cualquier necesidad de merge, deploy, gasto API separado, cambio de roles o creación de otra TASK
requiere nueva autorización explícita de Joaquín.
